## 3. Video folders, names, resolution and availability

- **Works in code â€” root configuration:** on PC, Android tablet and Android phone use Settings â†’ Media locations on this device â†’ Choose/change media root, one root per anime section (`new/src/screens/Settings.tsx:160`). Select the folder containing title folders; the expected suffix is title/season. Windows uses IFileOpenDialog and remembers approved roots (`new/windows/AnimeManager/CatalogStorage.h:142`, `:153`); Android uses ACTION_OPEN_DOCUMENT_TREE, stores the returned URI and attempts persistable grants (`new/android/app/src/main/java/com/animemanager/CatalogStorageModule.kt:47`, `:112`). A tablet is the same Android implementation, not a separate root mode. Failed/nonpersistable grants can require reselection after restart.
- **Works in code â€” relinking:** Details â†’ Relink title folder binds the season/media directory directly; Locate on an episode binds an exact file (`new/src/screens/Details.tsx:412`, `:510`). These override section-root inference, and settings are serialized locally (`new/src/app/useWorkspace.ts:80`). Missing media does not remove catalog entries.
- **Missing â€” create folders:** old add-anime actually calls `os.makedirs(root/title/season)` (`old/app.py:2619`); the setup script sanitizes/deduplicates title/season paths and has dry-run creation (`old/setup_anime_folders.py:13`, `:33`, `:57`). Native `createEntry` only creates relative references and catalog episodes (`new/src/services/library.ts:111`). Both native `mkdir` operations restrict writes to private app storage (`new/windows/AnimeManager/CatalogStorage.h:176`, Android module `:132`); neither exposes media-tree directory creation. Users must create title/season folders externally on all targets.
- **Partial â€” renaming:** old `rename_anime_paths.py:23` rebases saved paths with backup/dry-run; it explicitly does not rename media files. Native changing a root rebases lookup without catalog path rewriting. Manual relink compensates for physical folder/file renames; no native title/season rename, physical folder rename, episode-file rename, or editable relative-folder mapping is exposed. Do not characterize the old path-rewrite script as a file renamer.
- **Works in code â€” resolution order:** `new/src/services/media.ts:25` picks title override, otherwise resolves `root + relativeFolder`; `:54` first accepts an existing explicit episode-file override, then `:71` resolves `relativeFile`. If absent it shares one folder-list promise per check (`:80`), extracts episode numbers (`:7`), sorts, chooses a unique exact number, or uses ordinal mapping only when no file numbers start at 1 and file count equals episode-record count (`:91`). Checks run eight episodes at a time (`:111`). Player reruns this resolver before native open (`new/src/screens/Player.tsx:137`), so availability is not merely a painted badge.
- **Works in code â€” requested downloaded-name example:** with the selected season folder containing one `AnimePahe_Title_-_01v2_1080p.mp4`, expected `1.mp4` first fails direct lookup, then the separator/optional-vN regex extracts **1**, and the unique-number fallback returns that actual file URI (`new/src/services/media.ts:7`, `:91`). This is a source-derived result, not an executed filename test. Display title need not match the filename once the correct folder is found.
- **Partial â€” ambiguous/misleading names:** the regex uses the first eligible numeric token, so numbers in a title can beat the actual episode number. Duplicate releases are not reliably rejected: if no episode 1 exists and counts match, the ordinal branch may still select among duplicates. Absolute numbering with incomplete downloads fails ordinal mapping unless counts match. Only the current folder is scanned, not recursively; arbitrary moved folders are not discovered. Explicit Locate is the escape hatch. Old Flask mapping assigns sorted files by ordinal unconditionally (`old/app.py:521`); old Electron has its own checker (`old/main.js:351`), so native changes semantics rather than preserving two inconsistent implementations.
- **Partial â€” existence is not playable-file validation:** native Windows resolveChild returns any existing path (`new/windows/AnimeManager/CatalogStorage.h:190`); Android raw-path resolve also returns an existing child (`:97`) and SAF resolve matches names without requiring final file MIME (`:103`). A directory matching an expected filename, or an unreadable/unsupported file, can be labeled available. Directory errors become permission messages in TS; Android null provider query yields empty listing (`:86`), which can instead appear missing. No codec probe runs during checks.
- **Works in code â€” imported absolute paths:** legacy migration uses old directory suffix / explicit relative directory and extracts a relative episode filename; it strips known absolute path fields from retained records (`new/src/repositories/legacyImport.ts:101`, `:169`, `:191`). **Real Windows upgrade candidates (Missing from current code):** libmpv (FFmpeg decoding plus libass subtitle rendering, embedded track selection) and libVLC (broad container/codec/subtitle engine and embeddable native player). Integration cost is engineering and distribution work, not a quoted license fee: replace the engine behind CatalogPlayer's commands/state; map asynchronous events, track IDs/languages and completion; manage decoder lifetime/threading and errors; embed output in an HWND or implement a Fabric composition component; solve DPI/scroll/sheet occlusion/fullscreen/focus; package architecture-matched native binaries and codec/plugin/font dependencies; verify hardware decoding, seeking, subtitle types, crash recovery and installers. No schedule or performance claim is justified without a prototype. Distribution must follow the chosen builds' licenses: mpv defaults to GPL, with an LGPL build option; libVLC is LGPL, and bundled components have their own terms ([mpv Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright), [libVLC docs](https://videolan.videolan.me/vlc/master/libvlc.html)).
